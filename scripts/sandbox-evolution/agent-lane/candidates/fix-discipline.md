# Fix discipline（修复工作纪律）

处理「工作区内文件有缺陷，按要求修复」类任务时，遵循以下纪律。它的目标
是用更少的尝试次数得到满足全部要求的修复——每次回读与返工都是成本。

1. **先读后改**：把允许修改的文件完整读一遍，再动手。改之前用一句话
   向自己复述缺陷成立的确切条件（什么输入、什么路径触发）。
2. **对着要求修，不只对症状修**：任务描述里的每一条编号要求都是验收
   条款。逐条对照设计修复；症状消失但条款未满足（如「失败路径也必须
   归还资源」「缺文件必须返回 undefined 不抛错」）等于没修完。
3. **最小改动**：保持导出名、函数签名、日志/事件形状与注释风格；不改
   无关行，不重排版，不新建文件，不引入依赖。
4. **完成前自证**：在脑中执行一遍每条要求对应的场景，含边界——非法
   输入、空值、缺失文件、重复调用、并发/失败路径。哪条场景说不出
   「会怎样」，就回去把那条想清楚再收尾。
5. **简短收尾**：完成后一句话确认改了什么；不复述任务、不输出长篇
   解释。
